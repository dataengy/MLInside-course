# AI-глоссарий (RU)

> Термины, возникшие в рабочих сессиях по курсу MLInside 2026 (правила продакшена курса,
> генерация и публикация дек, изоляция параллельных агентских сессий, трекеры).
> Русские и русифицированные (сленговые) термины — здесь; англоязычные/инфра — в
> [AI-glossary.en.md](AI-glossary.en.md) (с переводом на русский). У каждого термина —
> перевод на второй язык и пример из сессии.
> Пополнение: skill-chain `add-terms-to-glossary` → `scan-session-for-new-glossary-terms-candidates` → `update-terms-glossaries`.
>
> **Легенда маркеров** — у каждого термина метка:
> `[общий]` = стандартный/переносимый, смысл сохраняется вне проекта;
> `[узкий]` = специфичный для этого курса/репозитория, понятен только с приведённым здесь контекстом.
> Порядок простые → сложные: сперва базовые, потом составные (опираются на базовые).
>
> **term-meta** — сразу после заголовка идёт машиночитаемая строка `<!-- term-meta {…} -->`
> (slug, регекс словоформ, перевод, метка, дата). Пустые необязательные поля не печатаются.
>
> Схема и словари: `~/.ai/skills/.settings/docs/docs_glossarize.yml` → `docs_glossarize.term_meta`.
> Проверка: `just -f ~/.ai/skills/_scripts/docs/glossary/Justfile terms-check` (заполненность)
> и `… terms-validate` (нарушения схемы).

## общее дерево

<!-- term-meta {slug: общее-дерево, match: "общее\ дерево", en: Shared checkout, tag: общий, added: 2026-08-26} -->

`[общий]` Рабочая копия репозитория, в которой одновременно работают несколько агентских сессий. Опасна не «грязью», а сменой ветки: чужой `git checkout` между вашими `commit` и `push` уводит коммит в чужую ветку. В общем дереве — только чтение, либо agent-lock и коммиты узким скоупом.
> **EN:** Shared checkout — a working tree several live agent sessions share.
> **Пример:** 2026-08-26: коммит ac7062c уехал в feat/preza-merge из общего дерева (#14).
> **См. также:** [worktree](AI-glossary.en.md#worktree), [agent-lock](AI-glossary.en.md#agent-lock)

## блок записи

<!-- term-meta {slug: блок-записи, match: "блок\ записи", en: Recording block, tag: узкий, added: 2026-08-26} -->

`[узкий]` Часть лекции, записываемая непрерывно; между блоками на записи делается пауза, чтобы монтажёр разрезал материал на уроки до 25 минут. План блоков ведётся по id слайдов и должен покрывать деку целиком, по порядку, без наложений.
> **EN:** Recording block — a chunk of the lecture recorded without a break; the editor cuts lessons on the pauses between blocks (≤25 min each).
> **Пример:** dbt-дека — 6 блоков (70 слайдов ≈ 91 мин); «dbt Core» разбит надвое, 24 сл. ≈ 31 мин > 25.
> **См. также:** [recording.blocks](AI-glossary.en.md#recordingblocks), [склейка](#склейка)

## дизайн-пасс

<!-- term-meta {slug: дизайн-пасс, match: "дизайн\\-пасс", en: Design pass, tag: узкий, added: 2026-08-26} -->

`[узкий]` Последний проход менеджера курса по презентации перед записью (единый размер шрифта, отступы, снятая обводка код-блоков). Опасность: правки делаются руками в `.pptx`, а деки собираются из YAML — если не перенести их в профиль форматирования генератора, следующий build молча их откатит.
> **EN:** Design pass — the manager's final formatting pass over a deck; must be ported into the generator, never left only in her file.
> **Пример:** #8: правки v3.15 перенесены профилем alina-2026-08 → сборка v3.19.1+alina-fmt.
> **См. также:** [форк деки](#форк-деки), [course_production](AI-glossary.en.md#course_production)

## форк деки

<!-- term-meta {slug: форк-деки, match: "форк\ деки", en: Reviewer's deck fork, tag: узкий, added: 2026-08-26} -->

`[узкий]` `.pptx`, который ревьюер (менеджер курса) вернул с правками, пока автор ушёл вперёд на несколько версий. Его нельзя просто взять: сборка идёт из YAML. Лента `preza-merge` разбирает трёхсторонний диф base/ours/theirs и переносит системные правила в профиль, отсекая регрессии пересохранения.
> **EN:** Reviewer's deck fork — an edited .pptx returned several versions behind ours.
> **Пример:** MLInside_Введение-в-dbt_v3.15 (1).pptx — форк Алины; наш HEAD тогда был v3.19.
> **См. также:** [дизайн-пасс](#дизайн-пасс), [блок записи](#блок-записи)

## тест-клип

<!-- term-meta {slug: тест-клип, match: "тест\\-клип", en: Test clip, tag: узкий, added: 2026-08-26} -->

`[узкий]` Короткое пробное видео перед первой лекцией: лицо, демонстрация экрана и звук. Менеджер показывает его монтажёру — тот подтверждает качество картинки и звука. Гейт: без него записывать лекции нельзя.
> **EN:** Test clip — a 1–2 minute trial recording the editor checks before real lectures.
> **Пример:** Тест-клип — p1 на 26.08; без ок монтажёра лекции не пишем.
> **См. также:** [склейка](#склейка), [блок записи](#блок-записи)

## склейка

<!-- term-meta {slug: склейка, match: "склейка", en: Splicing recorded chunks yourself, tag: узкий, added: 2026-08-26} -->

`[узкий]` Соединение записанных кусков лекции своими силами. Менеджер запретила: склейка теряет качество, монтажёр собирает сам. Правило зафиксировано скаляром `course_production.recording.no_splicing`.
> **EN:** Splicing recorded chunks yourself — forbidden; send the raw pieces to the editor.
> **Пример:** «Склеивать не нужно, лучше просто скинуть несколько кусочков» — Q&A №13.
> **См. также:** [тест-клип](#тест-клип), [блок записи](#блок-записи)

## ключ напоминания

<!-- term-meta {slug: ключ-напоминания, match: "ключ\ напоминания", en: Reminder key, tag: общий, added: 2026-08-26} -->

`[общий]` Строка `key: <slug>` в описании задачи, по которой повторный прогон находит её и синхронизирует срок/приоритет/текст вместо создания дубля. Устойчивее нечёткого совпадения по тексту: задачу можно переименовать руками, ключ переживёт.
> **EN:** Reminder key — a `key: <slug>` line in the task description anchoring an idempotent upsert.
> **Пример:** key: mlinside-record-dbt — второй прогон печатает `= OK`, а не создаёт вторую задачу.
> **См. также:** [MAX_PROJECTS_LIMIT_REACHED](AI-glossary.en.md#max_projects_limit_reached)

## снимок keep-листа

<!-- term-meta {slug: снимок-keep-листа, match: "снимок\ keep\\-листа", en: Keep-list snapshot, tag: общий, added: 2026-08-26} -->

`[общий]` Файл (`.ai/WiP/HANDOFF-<дата>-<тема>.md`), куда перед сжатием контекста выписывают открытые задачи с ключами, сделанное с SHA, **что не сделано и почему**, согласованные решения и команду resume. Инструкция компакции сохраняет лишь упоминания файлов, не их содержимое — без снимка проверять после сжатия нечего.
> **EN:** Keep-list snapshot — a committed session-state file that survives context compaction.
> **Пример:** .ai/WiP/HANDOFF-2026-08-26-course-rules-session.md (main 83d5361).
> **См. также:** [worktree](AI-glossary.en.md#worktree), [общее дерево](#общее-дерево)

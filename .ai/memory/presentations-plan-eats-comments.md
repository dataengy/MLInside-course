`content/presentations.yml` пересобирается YAML-сериализатором (`just presentations-plan`,
`presentations-plan-dry`). Курируемые **поля** он сохраняет — как и обещает шапка файла, —
но **комментарии не переживают прогон**: они не часть модели данных. Заодно снимаются
кавычки с заголовков (`'Quick Start и DEMO 1'` → без кавычек) — это косметика, а вот
комментарии унести можно навсегда.

**Why:** в этом файле комментарии несут причины, которых больше нигде нет, и без них
следующий проход «оптимизирует» странно выглядящую структуру обратно. Реальный случай
2026-09-01: прогон снёс восемь строк, в том числе (1) правило нарезки — ни одно живое
демо не должно попадать на стык блоков, пауза на монтаж идёт до или после показа;
(2) объяснение, почему приложение Dagster-деки разбито на ТРИ блока: иначе срабатывает
гейт «блок > 25 мин», потому что оценка идёт по эвристике 1.3 мин/слайд и не знает, что
приложение вообще не записывается; (3) указатель на сабмодуль с практикой. Потеря
обнаружилась только чтением diff'а глазами — ни один тест и ни один хук её не ловит.
Восстановлено коммитом `96e1a81` (версия `published` при этом осталась новой, 4.9/131).

**How to apply:** после каждого `just presentations-plan` — до коммита — прогнать
`git diff content/presentations.yml | grep '^-.*#'`; непустой вывод означает унесённые
комментарии. Возвращать их поверх новой версии (не откатывать файл целиком: правки
`published`/акцентов нужны), источник — `git show HEAD:content/presentations.yml`.
Тот же риск у любой ленты, которая переписывает YAML целиком, — например
`just preza-merge-apply` для `settings/formats.yml` (см. [[deck-footer-clearance]]).
См. также [[deck-images-registry]] — реестр картинок, который правится и руками, и скриптом.

## Что НЕ сделано и почему (самое важное — саммари это теряет первым)

1. **Drive-загрузка и колонки листа не выполнены**: нет права записи. У обоих сервис-аккаунтов
   `canEdit=False` (проверено `.tmp/probe_google_access.py`), ADC-консент не завершён.
   Два пути, оба требуют действия человека:
   - добить браузерный ADC-консент (скоупы `spreadsheets` + `drive.file`) → работает всё;
   - расшарить лист на `service-account-1@for-prodamus-1.iam.gserviceaccount.com` как
     **Редактор** и прописать ключ в `settings/publish.yml#auth.service_account_file` →
     работают только колонки; Drive-лег упадёт изолированно (у SA нет storage-квоты).
2. **`drive.file`, а не `drive`** — полный `.../auth/drive` restricted, экран согласия gcloud
   отвечает «Приложение заблокировано». Не возвращать обратно.
3. **`drive.folder_id` в `settings/publish.yml` = null** — заполняется один раз через
   `just publish-init-drive` после появления доступа.
4. **PR-свип: сводить нечего** — веток нет ни в одном разрешённом репозитории; OGIP
   (4 ветки) исключён владельцем (живая сессия + worktree); корпоративные `dbt.*`/`pdp.*`
   исключены политикой; бэкап-ветки мержить нельзя.

## Решения, которые НЕ пересматривать

- Триггер публикации только явный (`just publish-new`) — билдер мятит новую minor каждым
  билдом, авто-публикация = спам.
- Один файл на предмет без версии в имени; новая версия = `files().update` того же fileId.
- Telegram-отправкой владеет репо-лента; глобальный `deck-publish.yml → on_complete`
  остаётся `"open"`, иначе двойная отправка.
- dbt-дека рукописная — провенанс-штамп ей не ставить никогда.
- Трекер этого репо — GitHub Issues; Jira запрещена.

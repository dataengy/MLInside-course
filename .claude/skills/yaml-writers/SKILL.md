Файл конфигурации, который правят и машина, и человек, легко испортить незаметно:
`yaml.safe_load` + `safe_dump` сносит комментарии, оставляя **валидный YAML** и дифф,
похожий на безобидное переформатирование. Ни тесты, ни линтеры этого не ловят.
Реальный случай: один прогон унёс восемь строк пояснений, заметили только глазами в диффе.

Термины и таблица причин — `docs/glossary.md`, раздел «Запись YAML: три стратегии».

## Правило выбора

```
В файле есть комментарии или рукописное форматирование?
├─ нет ......................................... safe_dump (это нормально)
└─ да
   ├─ ценность в форматировании тела (блочные
   │  скаляры, кавычки, многоабзацные notes) ... блочная хирургия по тексту
   └─ ценность в данных, комментарии поясняют
      структуру ................................ round-trip (ruamel)
```

**safe_dump — не «устаревший способ».** Для машинного файла он правильный: дешевле и без
лишней зависимости. Ошибка не в нём, а в применении его к файлу с комментариями.

**Round-trip к контент-YAML деки применять нельзя.** Он нормализует блочные скаляры и
кавычки во ВСЁМ файле, и правка одного слайда приезжает диффом на тысячу строк. Там —
блочная хирургия: `scripts/preza/edit_slides.py`, `src/picstore/ids.py`.

## Round-trip: как не обмануться

Подключить ruamel мало. Комментарии живут **на объектах** (`CommentedMap`, `CommentedSeq`),
поэтому загруженный документ надо **мутировать по ключам**:

```python
doc = load_roundtrip(path)
entry = next(e for e in doc["presentations"] if e.get("out_name") == name)

entry["published"] = block            # ✗ выбросит комментарии со старой мапой
current = entry.get("published")      # ✓ правим на месте
for key in [k for k in current if k not in block]:
    del current[key]
for key, value in block.items():
    current[key] = value
```

Готовые хелперы: `schedule.settings.load_roundtrip` / `dump_roundtrip`. Обычный `dump_yaml`
там же оставлен для файлов без комментариев.

## Шумный round-trip

Комментарии выжили, но каждая запись даёт дифф. Четыре причины, все закрыты в хелперах —
если пишете свой, проверьте все:

| Симптом | Причина |
|---|---|
| `null` стал пустотой | ruamel печатает `None` пустым — нужен representer |
| пробелы в конце строк | перенос длинного скаляра ставится после пробела |
| шапка удвоилась | ведущий комментарий пришёл и из документа, и из кода |
| дифф на пол-файла | не совпали `width`/`indent` с прежним писателем |

Шапку файла держите канонической: снимайте с документа при чтении и дописывайте кодом.
Тогда её можно менять в одном месте — см. `_HEADER` в `preza_merge/apply.py`.

## Приёмка

Три проверки, без них правку считать незаконченной:

1. **Комментарии на месте** — сравнить количество `#`-строк до и после.
2. **Данные не поехали** — разобрать оба файла и сравнить деревья, а не текст.
3. **Вторая запись байт-в-байт равна первой.** Главный признак: если запись не
   идемпотентна, round-trip настроен не до конца.

Закрепить тестами. Образцы: `test_comments_survive_update` и
`test_repeated_writes_are_byte_stable` в `src/publisher/tests/test_plan_writer.py`,
такие же в `src/preza_merge/tests/test_apply.py`. Проверьте, что тест **падает** на
реализации через `safe_dump` — иначе он декоративный.

## Сторож

`scripts/hooks/yaml-writers-status.sh` (SessionStart) следит за двумя вещами: в охраняемых
файлах не убавилось комментариев против HEAD, и модули с обязательством round-trip не
вернулись к `yaml.safe_dump`. Заводя нового писателя, впишите файл в `GUARDED`, а модуль —
в `ROUNDTRIP`.

Сейчас на round-trip: `publisher/plan_writer.py`, `preza_merge/apply.py`, `schedule/cli.py`.
Охраняются: `content/presentations.yml`, `settings/formats.yml`.

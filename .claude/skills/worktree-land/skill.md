Посадка ветки worktree в `main` с удалением каталога. Скилл существует не ради экономии трёх
команд git, а ради одного факта: **`git worktree remove` уничтожает untracked-файлы без следа**
— их нет ни в одном коммите, восстановить нечем. В этом репозитории в одном worktree регулярно
работают несколько сессий сразу, и чужой незакоммиченный файл выглядит ровно так же, как свой.

## Порядок

```bash
scripts/worktree_land.sh check                    # только проверить, ничего не делать
scripts/worktree_land.sh land                     # проверить и влить в main
scripts/worktree_land.sh remove --force-remove    # проверить, влить, удалить
```

`check` — режим по умолчанию. Удаление требует явного `--force-remove`: забыть флаг
безопасно, забыть проверку — нет.

## Семь проверок

| # | Что | Почему блокирует |
|---|-----|------------------|
| 1 | Запуск не из удаляемого каталога | git откажется, а сессия останется без cwd |
| 2 | Нет незакоммиченных правок | пропадут вместе с каталогом |
| 3 | Нет untracked-файлов вне артефактов | **пропадут безвозвратно** — их нет в git |
| 4 | Всё выложено в origin | локальный коммит умрёт вместе с каталогом |
| 5 | Нет `git worktree lock` | замок — заявка «каталог занят», снимать за автора нельзя |
| 6 | Чьи коммиты в ветке | слияние утащит в main чужую работу; не блокирует, но показывается |
| 7 | Нет живых сессий в каталоге | **проверяется вручную** — см. ниже |

Собранные деки (`data/drafts/`, `data/generated/`) и промежуточные картинки (`.tmp/render*`,
`.tmp/build`) из проверки 3 исключены: они воспроизводятся сборкой. Фильтр работает только
при `core.quotePath=false` — иначе git экранирует кириллические имена дек в `"\320\222…"`,
и сравнение по префиксу пути молча перестаёт совпадать.

## Проверка 7: живые сессии

Bash их не видит — **вызовите `ListAgents`** и сопоставьте имена сессий с именем worktree.
Строка вида `preza-dbt-v4-0-2-5c · interactive · waiting` означает, что в каталоге
`preza-dbt-v4-0-2` прямо сейчас кто-то работает. Удаление оставит эту сессию без рабочей
копии посреди задачи.

Если сессии живы — не удалять. Написать им через `SendMessage`, дождаться, пока они
закоммитят и выйдут, и только потом повторить.

## Когда проверки красные

Не «обойти», а закрыть причину:

* незакоммиченное и untracked — **выяснить, чьё это**, прежде чем коммитить или удалять;
  файл в чужом лейне коммитит его автор, не вы;
* замок — снимает тот, кто ставил (`git worktree unlock`);
* «ветка уже в origin/main» — не ошибка, а сообщение: сливать нечего, остаётся уборка.

## Границы

Скилл не решает конфликты слияния и не делает force-push. `land` работает через
`fetch → rebase origin/main → push origin HEAD:main`; если ребейз встал на конфликте, дальше
человек разбирается сам. Удаление ветки на remote (`push origin --delete`) идёт последним
шагом и только в режиме `remove`.

Сиблинги: `workstation-bootstrapper` (весь репозиторий закоммичен и воспроизводим на новой
машине), `preza-merge` (правки ревьюера в генератор).

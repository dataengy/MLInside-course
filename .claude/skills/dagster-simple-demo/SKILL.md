Живые демо к деке `content/preza-dagster-simple-content.yml` (50 слайдов) лежат в самом
репозитории: `demo/02-dagster-simple/`. Спека лейна — **`docs/dagster-simple-demos.md`**,
сценарии показа — в README каждого демо, рядом с кодом.

Лейн целиком ведёт сабагент **`dagster-demo-keeper`** — его и звать на многошаговую
работу с демо; этот скилл нужен для одиночного прогона и как справочник по ловушкам.

> **Сначала проверить, о каких демо речь.** В репозитории их ДВА блока. Демо деки v2
> (113 слайдов) живут в сабмодуле `data/code/dagster_demo/`, спека
> `docs/dagster-demo-runbook.md`, порт 3111. Этот скилл — НЕ про них.
> Признак этого блока: путь `demo/02-dagster-simple/`, порт 3000, слайды 17 и 18–27.

## Что делать первым

```bash
just demo-test    # pytest обоих демо, ~15 с — быстрый ответ «код цел»
just demo-smoke   # оба сценария целиком без браузера, ~3 мин — ответ «демо цело»
```

Смоук каждого демо **сам возвращает состояние «до демо»** и заканчивается `SMOKE OK`.
Если нужно только вернуть состояние — `just reset` в папке демо.

## Состояние «до демо» — это НЕ «чисто»

Оба демо показывают **появление**: графа (демо 1), рёбер между загрузкой и dbt (демо 2).
Поэтому исходное состояние специально неполное:

| | демо 1 | демо 2 |
|---|---|---|
| `defs/` | пусто | только `resources.py` + `raw.py` |
| склад | `features.parquet`, срез 2018-03-01 | DuckDB удалён |
| источники dbt | — | **не сшиты** (нет `meta.dagster.asset_key`) |

Канон шагов лежит в `stash/`; рабочие копии в `defs/` — в `.gitignore`. Правленые вживую
файлы `reset` не теряет, а откладывает в `.reset-backup/`.

**`_sources.yml` — единственный файл ПОД ГИТОМ, который правит сам показ** (`just stitch`).
Канон, из которого `reset` его возвращает, — `stash/_sources.plain.yml`. Изменённый
`_sources.yml` в `git status` после демо означает «не сделали `just reset`», а не правку.
SessionStart-хук `dagster-demo-status.sh` это ловит.

## Три грабли — проверять в этом порядке

1. **`IO Error: Could not set lock on file ... Conflicting lock is held`**
   DuckDB пускает одного писателя, исполнитель Dagster многопроцессный. Нужен
   `pool="duckdb"` у всех, кто трогает файл, И **`granularity: op`** в
   `.dagster_home/dagster.yaml`. `granularity: run` читается как «по одному за раз», но
   ограничивает число одновременных ЗАПУСКОВ — внутри одного запуска шаги по-прежнему
   параллельны, и блокировка возвращается. Конфиг пишет `just reset`; держит `test_pool.py`.

2. **`Binder Error: Cannot compare values of type VARCHAR and type DATE`**
   CSV не несёт типов. `order_date` без явного разбора ложится в склад строкой, и падает
   не загрузка, а `feature_mart` тремя уровнями ниже. Типы сырья — ответственность
   ассета загрузки (`defs/raw.py`, `DATE_COLUMNS`). Держит `test_raw_load.py`.

3. **`@dbt_assets` не импортируется / manifest not found**
   Манифест нужен ДО импорта модуля. `prepare_if_dev()` работает только под `dg dev`;
   для `dg launch` и pytest его собирает `just _parse` (`dbt parse`).

## Сшивка — сердце демо 2, и она молчалива

Ребро `raw_orders → stg_orders` появляется только когда совпадают ДВЕ строки в разных файлах:

```python
# defs/raw.py          @dg.asset(key=dg.AssetKey(["raw_orders"]))
# _sources.yml         meta.dagster.asset_key: ["raw_orders"]
```

Переименуют ассет — **ничего не упадёт**: dbt не пожалуется, граф соберётся, источник
просто повиснет отдельным узлом без родителя, и демо покажет ровно то, что собиралось
опровергнуть. Единственная защита — `test_sources_stitch.py`; при правке ключей
прогонять его обязательно.

Посмотреть форму графа без браузера: `just graph` в папке демо 2 (рёбра, внешние узлы,
проверки). У него есть флаги ожиданий — ими пользуется смоук:
`--expect-edge raw_orders,stg_orders`, `--expect-no-edge …`, `--expect-min-checks 20`.

## В браузере: `just ui`

Демо смотрят в UI, поэтому есть прогон глазами браузера — репетиция и кадры для
screenshot fallback деки:

```bash
PORT=3001 just dev    # окно 1: сервер
PORT=3001 just ui     # окно 2: семь шагов, клики, проверки, кадры в .ui-shots/
```

`scripts/ui_walkthrough.py` кликает в UI то же, что человек (**Reload definitions**,
**Materialize all**), и проверяет, что видно обещанное: три ассета, `1 / 1 Passed`,
`roc_auc 0.6049`, `Unsynced (1)`, `0.6225`. Итог — `UI OK` или список несошедшегося.

**Порт.** По умолчанию 3000, но его часто держит соседняя сессия (в этом репозитории
параллельных сессий обычно несколько, и у каждой свой `dg dev`). Перед запуском
проверить `lsof -nP -iTCP:3000 -sTCP:LISTEN` и **не гасить чужой процесс** — взять
свободный порт через `PORT=`.

Три грабли, каждая стоила отладки:

1. **Движок — СИСТЕМНЫЙ Chrome**, `p.chromium.launch(channel="chrome")`. Свой хромиум
   playwright обычно не совпадает версией с кешем `~/Library/Caches/ms-playwright`:
   `Executable doesn't exist at .../chromium_headless_shell-NNNN`. Доустановить его в
   песочнице тоже нельзя (`EPERM ... __dirlock`), а системный Chrome уже стоит.
   Лестница движков — скилл `browser-automation-setup`; расширение claude-in-chrome
   в этом окружении не подключено.

2. **Граф свёрнут в группы.** `/asset-groups` рисует боксы `features` (2) и `ml` (1);
   имён ассетов в тексте страницы НЕТ, и проверка «есть feature_table» проваливается на
   живом графе. Раскрытие — параметром URL, ЧЕРЕЗ ЗАПЯТУЮ:
   `/asset-groups/?expanded=global@global:features,global@global:ml`
   (через `|` молча не раскрывается). Это же — ссылка «открыть раскрытый граф» на показе.

3. **`just reset` при поднятом сервере ломает `dg dev`**: он удаляет `.dagster_home`, где
   живой сервер держит SQLite. Поэтому `just ui` готовит состояние мягко — пересобрать
   признаки на срез по умолчанию и убрать `defs/ml.py`. История запусков остаётся, и
   проверки смотрят на ГРАФ, а не на `/runs`.

Слово в UI — **`Unsynced (N)`**, не «stale». После `just new-data` там ровно `Unsynced (1)`:
пометку получает только ПРЯМОЙ потомок, и это расхождение со слайдом записано в README демо.

## Числа, которые произносятся вслух

`rows 35`, `roc_auc 0.6049`, `features 6` — **одинаковые в обоих демо**, и это не совпадение:
витрина признаков считается дважды, на pandas (`scripts/make_features.py`, демо 1) и на SQL
(`feature_mart.sql`, демо 2), а `test_vitrina_dbt_sovpadaet_s_vitrinoj_pandas` сверяет их
колонка в колонку. Меняете одну — обязаны поменять другую, иначе демо 2 начнёт показывать
не те числа, чем демо 1.

Все числа со слайдов зафиксированы тестами. **Упавший тест на число — сигнал править
README/слайд, а не тест.** То же про тесты, фиксирующие расхождения со слайдами
(например `test_compute_kind_ne_daet_selektor_kind`).

## Общее сырьё и хардлинки

Сырьё jaffle shop и `scripts/status.py` — одни файлы на оба демо, связаны хардлинками,
реестр `demo/02-dagster-simple/files.yml`. **Git хардлинков не хранит**: после клона это
отдельные копии, и правка перестаёт доезжать. Проверить — `just demo-files-check`,
восстановить — `just demo-files-link` (связывает только совпадающие по sha256; разошедшиеся
по содержимому не трогает, их разбирают руками).

Добавляете общий файл — добавляйте и в `files.yml`, иначе `test_files_registry.py` о нём
не узнает, а копии тихо разъедутся.

## Расширять демо

- Новый шаг — файл в `stash/` + рецепт в `Justfile` + строка в таблице сценария README
  + проверка в `smoke` (через `just graph --expect-…` или `status.py --expect-stale`).
- Меняете витрину признаков — правьте **обе** реализации и прогоняйте `just demo-test`.
- Меняете `_sources.yml` — правьте **оба** файла в `stash/` (`_sources.plain.yml` и
  `_sources.stitched.yml`): `test_sources_stitch.py` требует, чтобы они отличались только `meta`.
- Новая версия Dagster/dbt — прогнать `just demo-smoke` и сверить разделы «Где код
  расходится со слайдами» в обоих README: они помечены версиями, на которых проверены.

Общий чекаут `/Users/user/gi/@dataengy/MLInside-course` — рабочий каталог **нескольких сессий
сразу**. Его `main` регулярно оказывается в состоянии, где `git pull` не проходит, а
`reset --hard` уничтожает чужую работу. Этот скилл — порядок, который это переживает.

## Сначала классифицировать, потом действовать

```bash
git fetch origin
git rev-list --left-right --count main...origin/main   # ahead<TAB>behind
```

| ahead | behind | что это | что делать |
|---|---|---|---|
| 0 | 0 | синхронно | ничего |
| 0 | N | отстали | `git merge --ff-only origin/main` |
| N | 0 | не выложено | `git push origin main` |
| N | M | **разошлось** | снимок → ребейз → сверка → push (ниже) |

Хук `repo-sync-status.sh` печатает четвёртый случай отдельной строкой `⛔ РАЗОШЁЛСЯ` — именно
потому, что две строки «ahead» и «behind» читаются как две независимые мелочи, а это одно
опасное состояние.

## Разошлось: порядок

1. **Не начинать, если в дереве чужая незавершённая работа.**
   `git status --porcelain | grep -v '^??'` — непусто значит: `rebase` откажет, а `merge`
   полезет ровно в те файлы, которые правят прямо сейчас. Найти автора (`ListAgents`),
   написать, дождаться коммита. Untracked-файлы сами по себе не мешают.
2. **Снимок до всего.** `git branch backup-local-main-$(date +%Y%m%d) main`. Имя по маске
   `backup-*` — `branch-pr-status.sh` считает такие снимками и не зовёт их мержить.
   Коммиты, которых нет на origin, существуют ТОЛЬКО на этой машине; ребейз перепишет им
   хеши, и без снимка откатываться будет некуда.
3. **`git rebase origin/main`** (не `merge`: история тут линейная, а merge-коммит в main,
   который никто не пушил, только путает).
4. **Сверить ПО СОДЕРЖИМОМУ, а не по «команда не ругнулась».** Для ключевых файлов сравнить
   blob/LFS-oid до и после: `git show <снимок>:<путь> | grep oid` против
   `git show <новый>:<путь> | grep oid`. Ребейз меняет хеш коммита — доказательством
   сохранности является совпадение содержимого, а не отсутствие ошибки.
5. `git push origin main`, затем `merge-base --is-ancestor <новый коммит> origin/main`.
6. **Только теперь** снять снимок: `git branch -D backup-local-main-…`.

`reset --hard origin/main` при ahead>0 не делать никогда — это молчаливое уничтожение
чужих коммитов, и именно оно выглядит как «синхронизация» в логах.

## Почему `git branch -d` отказывает, хотя всё слито

Три разные причины, лечатся по-разному:

* **локальный main отстал** — `-d` сверяется с HEAD, а не с origin. Сначала `merge --ff-only
  origin/main`, потом удалять;
* **протухший upstream** — на origin лежит ДОРЕБЕЙЗНАЯ версия ветки, git считает, что в неё
  не слито. Сначала `git push origin --delete <ветка>`, потом `-d`;
* **ветка занята worktree** — `cannot delete branch used by worktree at …`. Сначала убрать
  дерево (скилл `worktree-land`).

`-D` оправдан ровно в одном случае: ветка **побайтово равна** чему-то на origin
(`git rev-parse <ветка> origin/main | uniq | wc -l` = 1) или её содержимое уже сохранено
(например бандлом в `../.recyclebin`).

## Переключение ветки в общем чекауте удаляет файлы

`git switch` уносит из рабочей копии всё, чего нет в целевой ветке. За 2026-09-02 это дважды
стёрло правленные вручную деки пользователя из `data/drafts/`: закоммитил их на временную
ветку, вернулся на main — файлов нет. Восстановление: `git checkout <ветка> -- <пути>`, затем
`git restore --staged <пути>`, чтобы вернуть состояние «на диске есть, в индексе нет».

Поэтому **коммитить из общего чекаута через временную ветку — плохая идея**. Нужен
отдельный worktree (`EnterWorktree`), а общий чекаут пусть остаётся на main.

## Песочница

Запись в `../.recyclebin` и удаление каталогов под `.claude/worktrees/` падают с
`Operation not permitted` — корзина и служебные каталоги лежат вне разрешённой зоны, и это
НЕ про права файловой системы (`ls -l` показывает ваши же `rw-`). Лечится точечным
отключением песочницы на одну команду; правилами управляет `/sandbox`. Временные файлы
класть в `$TMPDIR`, а не в каталог задания.

Сиблинги: `worktree-land` (снос дерева), `recyclebin` (убирая — не удалять),
`workstation-bootstrapper` (всё закоммичено и воспроизводимо).

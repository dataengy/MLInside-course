# Claude-проект «MLInside | 2026/09» — руководство

Как устроен и как обслуживается проект в claude.ai (веб/десктоп), названный
**«MLInside | 2026/09»**: что в нём лежит, кто чем управляет, когда и чем обновляется.

Проект в claude.ai — **штаб курса**: там думают, формулируют, готовят сообщения и держат
контекст. Репозиторий `dataengy/MLInside-course` + Claude Code — **цех**: там всё, что
пишет файлы. Артефакты проекта (инструкции, память, знание, расписания) — их исходники
**лежат здесь, в репозитории**, потому что репозиторий синхронизирован между станциями,
а настройки проекта в облаке не версионируются и не диффятся.

| Артефакт проекта | SSoT в репо | Куда вставлять | Когда обновлять |
|---|---|---|---|
| Instructions | [`instructions.md`](instructions.md) | Project → Instructions | правила курса / роли / лента изменились |
| Memory | [`memory.md`](memory.md) | Project → Memory (или первым сообщением) | появился устойчивый факт о работе |
| Knowledge (файлы) | [`knowledge.md`](knowledge.md) | Project → Files | по чеклисту (см. ниже) или перед лекцией |
| Scheduled tasks | [`scheduled-tasks.md`](scheduled-tasks.md) | Project → Scheduled tasks | сдвинулись фазы курса |

Правило одно: **правим файл в репо → коммитим → переносим в облако**. Обратный порядок
(поправили в облаке, забыли в репо) убивает вторую станцию — она про правку не узнает.

## Границы: облачный проект vs Claude Code

У проекта в claude.ai **нет доступа к репозиторию** — ни к `content/*.yml`, ни к
`just`-рецептам, ни к Google Sheet. Он видит только то, что загружено в Knowledge и
вставлено в чат. Из этого следует разделение:

| Делает облачный проект | Делает Claude Code в репо |
|---|---|
| формулировки: письма Алине, ответы Владу, анонсы студентам | генерация и сборка дек (`just build`, `preza-*`) |
| разбор чата с менеджером → что из этого правило, что вопрос | правка `content/*-content.yml`, `settings/*.yml` |
| проверка структуры лекции «на глаз», по акцентам | `just preza-review`, `just preza-blocks` — по коду |
| черновики ДЗ и демо, идеи слайдов | `homework/`, публикация `just publish-new` |
| планирование недели, разбор «что горит» | коммиты, PR, секреты, синхронизация станций |

Практический шов: облачный проект **выдаёт текст, который человек переносит в репо** —
и в инструкциях явно требует помечать такой текст блоком с путём файла, чтобы Claude Code
на станции применил его одной командой.

## Первичная настройка (один раз)

1. Проект создан: **MLInside | 2026/09**.
2. **Instructions** — скопировать содержимое [`instructions.md`](instructions.md) между
   маркерами `<<<INSTRUCTIONS` / `INSTRUCTIONS>>>` в поле Instructions.
3. **Knowledge** — собрать комплект и загрузить:
   ```bash
   just claude-project-bundle       # → .tmp/claude-project-bundle/ + MANIFEST.md
   open .tmp/claude-project-bundle
   ```
   Перетащить содержимое папки в Project → Files. Состав и причины — [`knowledge.md`](knowledge.md).
4. **Memory** — вставить блоки из [`memory.md`](memory.md) (в UI памяти проекта либо первым
   сообщением в новом чате с просьбой запомнить).
5. **Scheduled tasks** — завести задачи из [`scheduled-tasks.md`](scheduled-tasks.md);
   расписания там уже проставлены.
6. Проверка: новый чат в проекте, вопрос «кто ведёт лекцию 6 и в каком состоянии её дека?».
   Ответ должен опираться на `presentations.yml` из Knowledge, а не на догадки. Если Claude
   отвечает общими словами — комплект не загрузился.

## Регулярное обслуживание

**Перед отправкой деки менеджеру** — обновить в Knowledge `presentations.yml`
и свежий отчёт `docs/reviews/<deck>.md`, иначе проект будет обсуждать прошлую версию.

**Раз в неделю** (закрывает scheduled task «Понедельничный разбор»): пересобрать бандл,
заменить файлы в Knowledge, снять галочки в `docs/course-qa.md`.

**Когда менеджер прислала новые правила** — сначала в репо
(`docs/course-rules.md` + `settings/config.yml → course_production`, лента агента
`course-production-keeper`), потом бандл, потом, если правило поменяло *поведение* —
абзац в [`instructions.md`](instructions.md) и перенос в облако.

**Когда всплыл устойчивый факт о работе** (не о курсе, а о том, как с ним работать) —
в [`memory.md`](memory.md) и в память проекта. Признак: факт переживёт текущую лекцию.

## Синхронизация двух станций

Станции: этот MacBook (`/Users/user/gi/@dataengy/MLInside-course`, пользователь `user`)
и **macCoreI9** (`/Users/nk.myg/github/@dataengy/MLInside-course`, пользователь `nk.myg`).
Снимки состояния — `.ai/workstations/*.yml` (ветка, HEAD, worktree'ы, id незакрытых
сессий, наличие файлов секретов без значений).

Облачный проект здесь — **третья точка правды и самая тупая**: он не знает, что где
закоммичено. Поэтому в его инструкциях запрещено утверждать состояние репозитория —
он обязан спрашивать или отвечать «проверь `just course-status` на станции».

Порядок переключения станции:

```bash
git status && git push                    # на покидаемой станции — ничего не оставлять
just -f ~/.ai/skills/_scripts/session/workstation/Justfile state --apply   # обновить снимок
# на второй станции:
git pull && git submodule update --init --recursive && git lfs pull
just secrets-bootstrap                    # если .env.secrets отсутствует (docs/secrets-sync.md)
just memory-pull                          # память Claude Code из .ai/memory/ (её нет вне git)
just repo-doctor && just course-status
```

Секреты через репозиторий и через облако **не ходят** — лента Bitwarden / git-secret,
руководство `docs/secrets-sync.md`.

## Чего в проекте быть не должно

- **Секреты**: `.env.secrets`, токены Google/Telegram/Todoist, service-account JSON.
  Загруженный в Knowledge файл живёт в облаке; отозвать проще токен, чем файл.
- **Тяжёлое и бинарное**: `.pptx`/`.pdf` из `data/` (git LFS, ~1.2 ГБ). Деку загружают
  в *чат* штучно, когда её реально обсуждают, а не в Knowledge.
- **Чужие деки как объект правки**: Apache Airflow — предмет Влада
  (`deck_generation.editing_excluded`). Читать можно, править — нет; найденный пробел
  оформляется как сообщение владельцу.
- **Собранные `.pptx` как источник правок**: деки генерируются из YAML, правка внутри
  файла умирает на следующей сборке (лента `preza-merge`, если правки пришли от ревьюера).

## Если что-то идёт не так

| Симптом | Причина | Что делать |
|---|---|---|
| Отвечает общо, без имён лекций | Knowledge не загрузился или устарел | пересобрать бандл, перезалить `presentations.yml` |
| Предлагает править `.pptx` | инструкции не перенесены в облако | заново вставить `instructions.md` |
| Говорит о версии деки, которой нет | старый `presentations.yml` в Knowledge | перезалить; версии — в `published.version` |
| Scheduled task приходит пустой | у задачи нет входных данных в Knowledge | перевести задачу в режим вопросов (см. `scheduled-tasks.md`) |
| Расходится с `just course-status` | облако не видит репозиторий | правда — на станции; облако правит только тексты |

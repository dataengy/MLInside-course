# Scheduled tasks проекта «MLInside | 2026/09»

Расписания, которые заводятся в Project → Scheduled tasks. Тексты промптов — исходники;
правятся здесь, потом переносятся в облако.

**Главное ограничение.** Задача выполняется без доступа к репозиторию: она видит только
Knowledge проекта. Значит, задача не может *проверить* состояние — она может **спросить,
свести и сформулировать**. Отсюда форма всех промптов ниже: сначала «вот что я вижу в
знании», затем «вот чего мне не хватает — ответь строкой», затем готовый текст.

Время подобрано вне круглых отметок — так задачи не толпятся.

Дай ровно три части:

## Что расписывать НЕ здесь

Облачные задачи не трогают файлы. Всё, что должно проверить или изменить репозиторий,
живёт на станции:

| Что | Чем | Где настроено |
|---|---|---|
| дедлайны и напоминания (запись, ответы, тест-клип) | Todoist, идемпотентно по `key:` | `settings/reminders.yml` → `just course-reminders[-apply]` |
| статус при старте сессии (дедлайн записи, деки без плана блоков, открытые вопросы) | SessionStart-хуки | `.claude/settings.json` → `scripts/hooks/*.sh` |
| публикация новой версии деки | Stop-хук / Prefect | `scripts/hooks/deck-publish-auto-send.sh`, `just publish-new` |
| разовое «через час напомни» внутри сессии | Claude Code, живёт только в этой сессии | `CronCreate` (авто-истекает через 7 дней) |
| регулярный агент с доступом к репозиторию | Claude Code | `/schedule` — проверить один прогон вручную, прежде чем полагаться |

Разделение простое: **Todoist держит сроки, хуки держат состояние, облачные задачи держат
мышление**. Дублировать дедлайны в облако не нужно — оно не узнает, что задача выполнена.

# Knowledge проекта «MLInside | 2026/09»

Какие файлы репозитория загружаются в Project → Files, зачем и как часто обновляются.
Комплект собирается воспроизводимо:

```bash
just claude-project-bundle      # → .tmp/claude-project-bundle/ + MANIFEST.md
```

Скрипт копирует файлы из рабочего дерева, режет то, что не нужно облаку, и пишет
`MANIFEST.md` с датой сборки и HEAD — по нему видно, насколько знание отстало от репо.

## Комплект

| Файл в бандле | Источник | Зачем проекту | Обновлять |
|---|---|---|---|
| `presentations.yml` | `content/presentations.yml` | план лекций, акценты, планы блоков, версии публикаций — главный файл | перед каждой отправкой деки; еженедельно |
| `course-rules.md` | `docs/course-rules.md` | правила менеджера: тайминг, блоки, дизайн, запись | при изменении правил |
| `course-qa.md` | `docs/course-qa.md` | что уже спрошено и отвечено + открытые вопросы | после каждого разговора с менеджером |
| `config-course.yml` | срез `settings/config.yml` (без ingest/paths) | люди, сроки, скаляры продакшена, стек | при изменении |
| `README-repo.md` | `README.md` | карта репозитория и командный словарь `just` | редко |
| `glossary-ru.md` | `.ai/AI-glossary.ru.md` | термины проекта — чтобы не переспрашивать | редко |
| `reviews/*.md` | `docs/reviews/<deck>.md` | последняя оценка деки по акцентам | после `just preza-review` |
| `homework-*.md` | `homework/mlinside-hw-olist/docs/HW*.md` | формулировки ДЗ | при правке ДЗ |

## Чего в комплекте нет — намеренно

- **`content/*-content.yml` целиком.** Деки по 70–125 слайдов; они забивают контекст и
  устаревают быстрее всего. Нужную деку загружают **в чат** на время разговора о ней.
- **Собранные `.pptx` / `.pdf` / картинки** (`data/**`, git LFS ~1.2 ГБ) — облаку нечего с
  ними делать, а Knowledge они переполнят. Конкретную деку — точечно в чат.
- **Любые секреты**: `settings/.env.secrets*`, `publish.yml` с путями к кредлам,
  service-account JSON. Файл, попавший в облако, отзывается хуже токена.
- **`settings/schedule.yml`** — сырой дамп листа; его курируемая версия и есть
  `presentations.yml`.

## Ритуал обновления

1. `just claude-project-bundle`
2. В проекте: удалить файлы с тем же именем, загрузить новые (замена «поверх» в UI
   ненадёжна — старая копия остаётся в контексте).
3. Сверить в чате: «какая последняя опубликованная версия dbt-деки?» — ответ должен
   совпасть с `published.version` в репозитории.

Признак протухшего знания: проект уверенно называет версию или статус, которых уже нет.
Это не «галлюцинация» — это старый файл в Knowledge, лечится перезаливкой.

# Глоссарий

Термины, которые в этом репозитории значат больше, чем в общем словаре: за каждым стоит
принятое решение и цена ошибки. Если термин встретился в коде или в заметке памяти и
непонятно, почему выбрано именно так, — он должен быть здесь.

---

## Запись YAML: три стратегии

Половина файлов конфигурации здесь правится **и машиной, и руками**. Как именно писать
такой файл — не вкусовщина: неверный выбор молча уничтожает работу человека, оставляя
валидный YAML и дифф, похожий на безобидное переформатирование.

### round-trip

Чтение и запись через `ruamel.yaml` с сохранением комментариев, порядка ключей и стиля
скаляров. В репозитории — `schedule.settings.load_roundtrip` / `dump_roundtrip`.

**Когда:** файл несёт структурированные данные **плюс комментарии**, и правят его обе
стороны. Сейчас таких два: `content/presentations.yml` и `settings/formats.yml`.

**Главное заблуждение:** «перевёл на ruamel — комментарии спасены». Нет. Комментарии в
ruamel живут **на объектах** (`CommentedMap`, `CommentedSeq`). Поэтому загруженный
документ надо **мутировать по ключам**, а не собирать новый:

```python
entry["published"] = {...}          # ← выбросит комментарии вместе со старой мапой
for k, v in block.items():          # ← правильно: правим на месте
    current[k] = v
```

**Признак, что сделано верно:** вторая запись подряд байт-в-байт равна первой. Если каждый
прогон даёт дифф — round-trip настроен не до конца (см. «шумный round-trip»).

### блочная хирургия

Файл режется на **текстовые** блоки, правится нужный, остальные остаются байт-в-байт.
YAML при этом парсится только для проверки, что результат не сломан и не изменился ни в
чём, кроме намеренного.

**Когда:** ценность файла — в рукописном форматировании, которое любой сериализатор
нормализует. Это контент-YAML дек: многоабзацные `notes:` блочными скалярами, намеренные
кавычки, шапки-комментарии. Round-trip здесь **вреден**: правка одного слайда приезжает
диффом на тысячу строк.

Реализации: `scripts/preza/edit_slides.py` (правка по `id` слайда),
`src/picstore/ids.py` (вставка одной строки с доказательством, что больше ничего не
изменилось), `scripts/preza/notes_fix.py`.

### safe_dump

Обычная пара `yaml.safe_load` + `yaml.safe_dump`. Комментарии не переживают — они не часть
модели данных.

**Когда:** файл целиком машинный, комментариев в нём нет и не предполагается.
Например `settings/schedule.yml` (сырой дамп таблицы), каталоги `librarian`,
`content/*-images.yml` (шапка дописывается кодом, внутри комментариев нет).

**Не «устаревший способ».** Для машинного файла это правильный выбор: дешевле, предсказуемее
и без зависимости от ruamel. Ошибка — не в `safe_dump` как таковом, а в применении его к
файлу с комментариями.

### Как выбрать

```
В файле есть комментарии или рукописное форматирование?
├─ нет ......................................... safe_dump
└─ да
   ├─ ценность в форматировании тела (блочные
   │  скаляры, кавычки, многоабзацные notes) ... блочная хирургия
   └─ ценность в данных, комментарии поясняют
      структуру ................................ round-trip
```

### Шумный round-trip

Round-trip, который сохраняет комментарии, но всё равно даёт дифф на каждой записи.
Четыре типовые причины, все закрыты в `schedule.settings`:

| Симптом | Причина |
|---|---|
| `null` превратился в пустоту | ruamel по умолчанию печатает `None` пустым — нужен representer |
| в конце строк появились пробелы | перенос длинного скаляра ставится после пробела |
| шапка файла удвоилась | ведущий комментарий пришёл и из документа, и из кода |
| дифф на пол-файла при первой записи | не совпали `width` и `indent` с прежним писателем |

## Термины лент

**Лента (lane)** — сквозной путь «вход → артефакт → проверка», у которого есть owner-агент,
спецификация в `docs/*-lane.md` и рецепты `just`. Ленты намеренно не пересекаются по
файлам записи: две ленты, пишущие один файл, — источник гонок (см. `docs/preza-merge-lane.md`).

**Гейт** — проверка, которая не даёт продолжить: `just preza-lint`, `course blocks --strict`,
`just check`. Отличается от статус-хука, который только сообщает.

**Статус-хук** — `scripts/hooks/*.sh`, вызывается на `SessionStart` и печатает расхождения,
ничего не блокируя.

**Сквозной инвариант** — свойство, которое обязано держаться после любой ленты. Примеры:
у деки все слайды покрыты блоками записи без дыр; комментарии в `presentations.yml` на месте;
в `origin/main` нет незапушенных коммитов сабмодулей.

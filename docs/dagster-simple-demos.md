## Прогнать всё

Из корня репозитория:

```bash
just demo-test         # только pytest обоих демо — быстро (~15 с)
just demo-smoke        # полный прогон обоих сценариев без браузера (~3 мин)
just demo-files-check  # сырьё и status.py одинаковы во всех демо
```

Прогон **через браузер** (пока только демо 1) — репетиция и кадры для screenshot fallback:

```bash
cd demo/02-dagster-simple/01-quickstart
PORT=3001 just dev    # окно 1: сервер
PORT=3001 just ui     # окно 2: семь шагов с кликами и проверками, кадры в .ui-shots/
```

Порт по умолчанию 3000 занимают соседние сессии — проверить
`lsof -nP -iTCP:3000 -sTCP:LISTEN` и взять свободный через `PORT=`, чужой `dg dev` не гасить.

Оба смоука заканчиваются строкой `SMOKE OK` и **сами возвращают состояние «до демо»**.
Сеть не нужна: окружения уже собраны (`uv sync` — в `just setup` каждого демо).

Показ — из папки конкретного демо: `cd demo/02-dagster-simple/01-quickstart && just dev`.

## Что гарантируют тесты (51 штука)

Тесты здесь не для покрытия, а для **обещаний, которые произносятся вслух на записи**.
Числа со слайдов зафиксированы: если витрина поедет, упадёт тест, а не демо на камере.

| Обещание | Кто держит |
|---|---|
| `rows 35`, `roc_auc 0.6049`, `features 6` — в обоих демо | `test_assets.py`, `test_ml_assets.py` |
| Витрина признаков на SQL (демо 2) и на pandas (демо 1) — **одна и та же** | `test_feature_mart.py::test_vitrina_dbt_sovpadaet_s_vitrinoj_pandas` |
| Утечки будущего в признаках нет | `test_make_features.py`, `test_feature_mart.py` |
| Ключи сшивки в `_sources.yml` и в `defs/raw.py` совпадают | `test_sources_stitch.py` |
| `just stitch` меняет **только** `meta`, ничего больше | `test_sources_stitch.py` |
| Свежесть 12 ч WARN / 24 ч FAIL | `test_assets.py` |
| 6 моделей и 26 dbt-тестов в манифесте | `test_dbt_project.py` |
| Пул `duckdb` объявлен везде, гранулярность `op` | `test_pool.py` |
| Сырьё одинаково во всех демо | `test_files_registry.py` |

Отдельный класс тестов — **фиксация расхождений со слайдами**. Например,
`test_compute_kind_ne_daet_selektor_kind`: `compute_kind="pandas"` рисует бейдж, но
селектор `kind:pandas` ничего не находит. Если Dagster однажды это сведёт вместе, тест
упадёт — и править надо будет README демо, а не тест.

## Что видно в UI, но не видно смоуку

`just smoke` проверяет граф через API, а зритель смотрит в интерфейс — и три вещи там
устроены не так, как ждёшь:

| В UI | Чего ждёшь | Как на самом деле |
|---|---|---|
| Глобальный граф | три узла | два бокса групп, `features` (2) и `ml` (1); ассеты — внутри, группы надо раскрыть |
| Устаревшее | «stale» | `Unsynced (N)`; после `new-data` ровно `Unsynced (1)` — только прямой потомок |
| Раскрытый граф ссылкой | любой разделитель | только запятая: `?expanded=global@global:features,global@global:ml` |

Это проверяет `just ui` (`scripts/ui_walkthrough.py`), а не pytest: тесты не поднимают
браузер. Движок — системный Chrome, потому что хромиум playwright расходится версией с
кешем; спека — скилл `browser-automation-setup`.

## Три грабли, каждая стоила прогона

1. **`granularity: run` ≠ «по одному за раз».** Пул DuckDB ограничивает число
   одновременных ЗАПУСКОВ; шаги внутри одного запуска продолжают идти параллельно, и
   блокировка файла возвращается. Нужен `granularity: op`. Держит `test_pool.py`.
2. **CSV не несёт типов.** `order_date`, загруженный без явного разбора, ложится в склад
   строкой, и падает не загрузка, а dbt-модель тремя уровнями ниже
   (`Cannot compare values of type VARCHAR and type DATE`). Держит `test_raw_load.py`.
3. **Манифест нужен ДО импорта.** `prepare_if_dev()` работает только под `dg dev`;
   для `dg launch` и pytest манифест собирает `just _parse`. Иначе `@dbt_assets`
   не импортируется вовсе.

## Состояние «до демо» и почему оно важно

Оба демо показывают **появление** чего-то: графа (демо 1), рёбер между загрузкой и dbt
(демо 2). Поэтому «до демо» — это не «чисто», а «специально неполно»:

| | демо 1 | демо 2 |
|---|---|---|
| `defs/` | пусто | только `resources.py` + `raw.py` |
| склад | `features.parquet` на срез 2018-03-01 | DuckDB удалён |
| источники dbt | — | **не сшиты** (нет `meta.dagster.asset_key`) |

`just reset` в каждом демо возвращает ровно это. Правленые вживую файлы он не теряет —
откладывает в `.reset-backup/`.

**`_sources.yml` — единственный файл под гитом, который демо правит по ходу показа**
(`just stitch`). Канон, из которого `reset` его возвращает, лежит рядом:
`stash/_sources.plain.yml`. Если после демо `git status` показывает изменённый
`_sources.yml` — просто не сделали `just reset`.

## Хардлинки и git

Сырьё jaffle shop и `scripts/status.py` — одни и те же файлы в обоих демо, связанные
хардлинками; реестр `demo/02-dagster-simple/files.yml`.

**Git хардлинков не хранит.** После клона на новой машине это будут обычные отдельные
файлы с тем же содержимым: всё работает, но правка в одной папке перестаёт доезжать до
другой. Восстановить связь — `just demo-files-link`, проверить — `just demo-files-check`
(он сверяет по sha256, а расхождение инодов сообщает мягко, потому что после клона оно
ожидаемо).

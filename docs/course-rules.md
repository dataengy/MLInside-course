## Пайплайн одной лекции

1. **Готовая презентация → в чат менеджеру** — по готовности, не обязательно все сразу.
   Перед отправкой у нас: `just preza-lint` → `just preza-validate` → `just preza-review` →
   `just preza-blocks <content>` → сборка → `just publish-new` (TG + Drive + колонки листа).
2. **Влад смотрит и «окает»** — при необходимости (в личке; его запись лекции — ориентир по
   формату).
3. **Менеджер проверяет дизайн** и делает мелкие правки (шрифт, отступы, обводки). После её
   прохода версия — финальная для записи.
4. **Пробная запись 1–2 мин** (лицо + демонстрация экрана + звук) → менеджер показывает
   монтажёру, тот подтверждает качество картинки и звука.
5. **Запись блоками** с паузами между блоками (см. «Планы блоков записи»). Не склеивать самим.
6. **Монтаж** режет запись на уроки до ~25 минут. Домашки можно доделывать параллельно с
   монтажом.

## Правила

### Тайминг и блоки

- Ограничений по длительности нет; **50 минут – 1,5 часа — «отлично»**
  (`lecture.duration_min: [50, 90]`).
- Запись режут на уроки **до 25 минут** (`lecture.block_max_min`) → лекцию заранее делим на
  смысловые блоки и на записи между блоками делаем **паузу**. Если в блоке мало материала,
  блоки можно объединять.
- План блоков — `content/presentations.yml → recording.blocks` (`from`/`to` — **id слайдов**,
  устойчивы к перестановкам); покрытие и оценка минут — `just preza-blocks <content>` /
  `just preza-blocks-all` (`--md` для вставки сюда, `--strict` для гейта). Оценка =
  слайды × `lecture.min_per_slide` (1.3; ~50-слайдовую v3.10 Николай оценивал в 50–90 мин)
  — эвристика, репетиция с секундомером важнее.
- Ограничений по **числу слайдов нет** — первичен тайминг (`lecture.slides_limit: null`).
  `deck_generation.slides_min/max` в `settings/config.yml` — наш внутренний гейт
  генератора, не требование курса.

### Дизайн

- Макет **финальный** (`design.template_final`). Менеджер уже выровняла размер шрифта и
  отступы в присланных `.pptx` (dbt v3.15, Dagster v1.4) и сказала «можно прямо в них
  исправлять». ⚠ Наши деки собираются из YAML — эти правки надо перенести в
  `content/build_deck_v3-settings.yml` / рендерер, иначе следующая сборка их потеряет
  (открытый пункт в [course-qa.md](course-qa.md#открытые-вопросы)).
- **Капслок в заголовках** — «вроде бы везде ок»; менять только там, где теряется смысл
  (аббревиатуры) (`design.headings_caps`).
- **Код-блоки**: белый на чёрном — ок; синюю обводку менеджер убрала; плохие переносы —
  поправить. Подсветка синтаксиса — опционально: на другом курсе код писали в редакторе,
  делали скрины и вставляли картинками — «было норм» (`design.code_blocks`).
- Блок **«доп. материалы»** внизу справа — ок, оставляем (`design.extra_materials_block`).
- Финальную версию всегда отправлять менеджеру на последний проход
  (`design.manager_final_pass`).
- Текст спикера под слайдами (notes) — есть и полезен при ревью; оставляем.

### Запись

- **Не склеивать** — слать отдельные кусочки, монтажёр соберёт сам: так сохраняется
  максимальное качество (`recording.no_splicing`).
- Место: **светлый (желательно однотонный) фон**, **без окна в кадре** — иначе засветы
  (`recording.background`).
- ПО для записи — по инструкции менеджера:
  [Google Doc](https://docs.google.com/document/d/1Ciq1WCZ4nYKdpQBkrSanVE0xGtg5rcSoVmaVoIz4voc/edit?usp=sharing)
  (`recording.software_guide`).
- Перед первой лекцией — **пробное видео 1–2 мин** с лицом, демонстрацией экрана и звуком
  → монтажёру на проверку (`recording.test_clip_min`).
- Между блоками — паузы (см. выше); внутри блока запись не прерывать.

### Сроки

- **Записать всё в августе** (`deadlines.record_all_by: 2026-08-31`, «ооочень важно») —
  чтобы в сентябре анонсировать модуль студентам (`deadlines.announce_module: 2026-09`).
  Хук `course-production-status.sh` считает дни и сигналит о просрочке.
- Запись до 9 августа была неудобна (отпуск) — менеджер согласилась на «через неделю, в
  удобных условиях»; до записи — доделать презы и домашки.
- ДЗ можно доделывать после записи, пока идёт монтаж.

### Домашние задания

- Студенты делают ДЗ **самостоятельно, их не проверяют** (`homework.checked: false`).
- Открытый вопрос менеджера — **нужна ли балльная система** (`homework.grading_scale:
  open`). Наши слайды «ДЗ: критерии оценки» (dbt `050-dz-kriterii-ocenki`, Dagster
  `049-dz-kriterii-ocenki`) и `homework/mlinside-hw-olist/docs/HW*.md` пока в баллах →
  [course-qa.md](course-qa.md#открытые-вопросы).
- Домашки после черновика — на ревью Владу (договорённость из чата).

## Напоминания

Открытые вопросы и сроки продублированы задачами в Todoist (проект «MLInside»), чтобы дедлайн
менеджера не жил только в доке. Источник — [`settings/reminders.yml`](../settings/reminders.yml)
(что напоминать, срок, приоритет, лейблы, текст); логика плана — `src/course/reminders.py`,
мутирующий вход — `scripts/todoist/upsert_reminders.py`:

```bash
just course-reminders          # план: что создать / что синхронизировать (без записи)
just course-reminders --list   # что сейчас в проектах ленты
just course-reminders-apply    # применить
```

Идемпотентность — по [ключу напоминания](../.ai/AI-glossary.ru.md#ключ-напоминания): в описании
задачи лежит строка `key: <key>`, повторный прогон находит задачу по ней и выравнивает поля
вместо создания дубля. Задачу можно переименовать или передвинуть руками; свои лейблы лента не
снимает. Задача, созданная до появления ленты, принимается полем `adopt: <task_id>`.

Ёмкость проектов Todoist (free-тариф — 8 активных, Inbox включительно) —
`just -f ~/.ai/skills/_scripts/tasks/todoist/Justfile projects-capacity`; при 8/8 создание нового
проекта отвечает [MAX_PROJECTS_LIMIT_REACHED](../.ai/AI-glossary.en.md#max_projects_limit_reached).

## Как обновлять

Новые договорённости из чата → `course_production` (скаляры) → этот файл (нарратив) →
[`course-qa.md`](course-qa.md) (пара вопрос/ответ; открытые — чекбоксы `- [ ]` в разделе
«Открытые вопросы») → при изменении структуры лекции `recording.blocks` →
`just preza-blocks-all && just course-status && just test`. Владелец ленты — сабагент
[`.claude/agents/course-production-keeper.md`](../.claude/agents/course-production-keeper.md);
кандидат скилла `course-rules-upsert` (`~/.ai/skills/_skills_candidates_by_prj/MLInside-course/`).
